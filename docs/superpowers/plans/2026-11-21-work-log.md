# Registro de trabajo — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Medir automáticamente las sesiones de una cuenta de Claude Code elegida y, al cerrarlas, guardar en una sección nueva «Registro de trabajo» la tarea macro con sus subtareas y los tiempos de Claude y Total.

**Architecture:** Los hooks HTTP de Claude, instalados por cuenta con la cabecera `x-notch-account`, llevan los eventos al puente existente. Un módulo Rust nuevo, `work_log`, mide los tramos de forma incremental, guarda `work-log.json` con el patrón de Notas y, al recibir `SessionEnd`, lanza `claude -p` con `CLAUDE_CONFIG_DIR` de la cuenta para que agrupe los tramos en subtareas. Los tiempos los calcula siempre el notch. El renderer añade una vista lista y detalle (como Redmine), una tarjeta, un bloque en la cápsula y dos páginas de Control Center.

**Tech Stack:** Tauri 2 (Rust, tokio), React 19 + Tailwind 4, zod con espejo en Rust, vitest, cargo test, WebdriverIO e2e.

**Spec:** `docs/superpowers/specs/2026-11-21-work-log-design.md` (léelo antes de cualquier tarea).

## Global Constraints

- Rama `feat/work-log` desde `dev`. Nada de commit, push ni PR sin aprobación del usuario: cada paso «Commit» se propone y se espera el sí.
- Ajustes v9 → v10 con migración automática solo en Rust (`src-tauri/src/settings/store.rs` `migrate`).
- Contratos: cada esquema zod nuevo tiene su espejo en `src-tauri/src/contract/*`; canal o evento nuevo → `src/shared/ipc/{channels,contract}.ts`, `portedChannels`/`portedEvents` en `tests/unit/shared/parity.test.ts`, casos en `tests/parity/contract-cases.json`, y `PARITY_UPDATE=1 npx vitest run tests/unit/shared/parity.test.ts`.
- Nunca se escriben en logs el prompt, la respuesta, el resumen ni el transcript; solo códigos de error.
- Textos en español e inglés en `src/shared/i18n/messages.ts`; tiempos con el formato `1h 25m` (`25m`, `2h`, `0m`).
- `DESIGN.md` manda en colores, tipografías y componentes; la integración se llama `workLog` y su color por defecto es `cyan`.
- Pausa por defecto 30 min, rango 5–240; tiempo límite del resumen 300 s.
- No editar `eslint.config.mjs` ni los hooks del repositorio.
- Gates antes de dar una tarea por buena: `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:rust`; las e2e del área tocada (el Developer Notch instalado debe estar cerrado: pedírselo al usuario).

## Review Focus

1. **Hooks de la 0.3.0 sin `x-notch-account`** → se atribuyen a la cuenta `claude` y el arranque los actualiza; la cuenta personal nunca deja de funcionar. Test en Task 2.
2. **`claude` no está en el PATH, devuelve JSON inválido o tarda más de 300 s** → la entrada queda «sin resumen» con sus tiempos y un título provisional; Reintentar funciona. Test en Task 6.
3. **Claude asigna un tramo a dos subtareas, inventa ids o deja tramos sin asignar** → cada tramo cuenta una sola vez; los sobrantes van a «Otros»; la suma de las subtareas es el Total. Test en Task 6.
4. **Un `Stop` que no llega (Esc) y un `UserPromptSubmit` con tramo abierto** → el tramo anterior se cierra en su último evento, sin tiempo fantasma. Test en Task 4.
5. **El notch arranca con entradas «en curso» guardadas** → pasan a «en pausa»; un evento posterior de esa sesión las reanuda sin duplicar la entrada. Test en Task 5.

### Task 4: Medición (núcleo puro)

**Files:**
- Create: `src-tauri/src/work_log/timing.rs` (+ `timing_tests.rs`)

**Interfaces:**
- Consumes: `HookEvent`, `HookEventName` (Task 2).
- Produces:
  ```rust
  pub struct Turn { pub id: String, pub prompt_id: Option<String>, pub prompt: String, pub reply: Option<String>,
                    pub tools: BTreeMap<String, u32>, pub started_at: i64, pub ended_at: Option<i64>,
                    pub last_event_at: i64, pub wait_ms: i64, pub wait_since: Option<i64>, pub excess_after_ms: i64 }
  pub struct Session { pub started_at: i64, pub last_event_at: i64, pub excess_before_ms: i64, pub turns: Vec<Turn> }
  impl Session {
      pub fn start(at: i64) -> Self;
      pub fn apply(&mut self, event: &HookEvent, at: i64, cap_ms: i64);
      pub fn close(&mut self, at: i64);            // cierra el tramo abierto en su last_event_at
      pub fn claude_ms(&self) -> i64;
      pub fn total_ms(&self) -> i64;               // last_event_at - started_at - excesos
      pub fn turn_totals(&self) -> Vec<i64>;       // reparto; suma == total_ms()
      pub fn live_total_ms(&self, now: i64, cap_ms: i64) -> i64;
  }
  ```

Algoritmo (no lo fija la firma):
- Cada evento en `at`: `gap = at - last_event_at`. Si **no** hay tramo abierto y `gap > cap_ms`, el exceso `gap - cap_ms` se suma a `excess_after_ms` del último tramo cerrado, o a `excess_before_ms` si aún no hay tramos. Dentro de un tramo abierto no hay exceso. Después `last_event_at = at` (y el del tramo abierto).
- `UserPromptSubmit`: si hay tramo abierto, se cierra en su `last_event_at` (antes de calcular el hueco); abre un tramo con `id = prompt_id` o `"t<n>"`, `prompt` de `work.prompt`.
- `PreToolUse`/`PostToolUse`/`PostToolUseFailure` en tramo abierto: cuentan la herramienta (`tools[name] += 1` solo en `PreToolUse`) y, si `wait_since` está puesto, suman `at - wait_since` a `wait_ms` y lo limpian.
- `PermissionRequest` y `PreToolUse` de `AskUserQuestion` (ruta `/hook/question`): `wait_since = at`.
- `Stop`/`StopFailure`: cierra el tramo abierto en `at` y guarda `reply`.
- `claude_ms` = Σ (`ended_at - started_at - wait_ms`), nunca negativo.
- `turn_totals[i]` = (inicio del tramo i+1, o `last_event_at` para el último) − `started_at` del tramo i − `excess_after_ms`; el primero suma además `started_at(t0) - session.started_at - excess_before_ms`.
- `live_total_ms(now)` = `total_ms()` + `now - last_event_at` − (si no hay tramo abierto) `max(0, now - last_event_at - cap_ms)`.

- [ ] **Step 1: Tests** (minutos como `M = 60_000`, `cap = 30*M`):

  - Sin tramos: `start(0)`, `SessionEnd` en 50M → `total_ms == 30M`, `claude_ms == 0`, `turn_totals == []`.
  - `live_total_ms` tras un Stop en 10M, consultado en 55M → `40M` (10 + 30 de tope).
