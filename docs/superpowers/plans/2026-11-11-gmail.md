# Gmail en el notch — Hito 1: base — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Contador de sin leer de Principal en la cápsula y vista "Gmail" con los 5 correos más recientes (abrir en el navegador), con inicio de sesión OAuth desde Control Center.

**Architecture:** Esquemas compartidos → auth OAuth (PKCE + loopback en `127.0.0.1`) y token cifrado con `safeStorage` → cliente REST con `fetch` y zod → integración Electron (ritmo 60 s, pausa, espera creciente, eventos) → cápsula, vista `gmail` y página de Control Center. Sin SDK de Google.

**Tech Stack:** Electron 45, TypeScript 6, React 19, Zustand, zod 4, Lucide, Vitest, Playwright `_electron`.

**Spec:** `docs/superpowers/specs/2026-11-11-gmail-design.md`.

## Global Constraints

- Una cuenta; solo `in:inbox category:primary`; lista de **5**; contador hasta 100 (100 = `99+`).
- Permiso único: `https://www.googleapis.com/auth/gmail.readonly`. La cuenta sale de `users/me/profile`.
- OAuth para apps instaladas: PKCE **S256**, `state` aleatorio, redirección `http://127.0.0.1:<puerto aleatorio>/callback`, navegador del sistema (`shell.openExternal`), servidor de retorno solo en `127.0.0.1`, vida máx. **5 min**.
- Token de refresco solo en main, cifrado con `safeStorage` en `userData/gmail-token.bin`; sin cifrado disponible no se persiste. Token de acceso solo en memoria.
- Ritmo: contador cada **60 000 ms** con la cápsula visible; nada en `mini`/`hidden`; consulta al reanudar; `refresh` manual con mínimo **5 s**; espera creciente en fallo de red/5xx/429: 1 → 2 → 4 → 5 min (máx.).
- 401 → refrescar una vez → si falla, `expired`.
- `SETTINGS_VERSION` 3 → **4** con `gmail: { clientId: '', clientSecret: '' }`; cambiar `clientId` cierra sesión.
- Log: nunca tokens, secreto, remitentes, asuntos ni extractos (solo estados, recuentos y códigos).
- Canales: `gmail:recent|view|refresh|open` solo notch; `gmail:sign-in|cancel-sign-in|sign-out` solo Control Center; `gmail:get-state` ambos; evento `gmail:state` a ambos.
- URLs abiertas construidas por main: `https://mail.google.com/mail/u/0/#inbox/<threadId>` o `https://mail.google.com/mail/u/0/#inbox`.
- URLs base (API y OAuth) inyectables. En `index.ts`, como los demás interruptores de desarrollo: `NOTCH_GMAIL_BASE_URL` se ignora si `app.isPackaged` y solo se acepta un origen `http://127.0.0.1:<puerto>`.
- i18n ES/EN; ≥ 24 px; tokens de `DESIGN.md`; texto de correos siempre como texto. Sin commits por tarea. No modificar `eslint.config.mjs`. Nunca manejar el escritorio del usuario ni su navegador.

## Review Focus

1. **Arranque sin red con token guardado** → estado `offline` (no `expired` ni `signed-out`), reintenta y pasa a `ok` al volver la red (Task 5).
2. **Iniciar sesión dos veces o cancelar a medias** → un solo servidor de retorno vivo; cancelar lo cierra y el estado vuelve a `signed-out` (Task 2, Task 5).
3. **Cambiar el `clientId` con sesión abierta** → se borra el token y el estado pasa a `signed-out` sin peticiones con el cliente viejo (Task 5).
4. **Cabeceras raras** (`"Doe, John" <j@x.com>`, sin nombre, sin asunto, `Date` ausente o inválida) → remitente legible, "(sin asunto)", fecha de `internalDate` (Task 4).
5. **El token se revoca con la vista abierta** → la vista pasa a "Vuelve a iniciar sesión" sin bucles de refresco (Task 4, Task 5).

### Task 2: Auth OAuth (PKCE + loopback)

**Files:** Create `src/main/gmail/gmail-auth.ts`, `src/main/gmail/loopback.ts`; tests `tests/unit/main/gmail-auth.test.ts`, `gmail-loopback.test.ts`.

**Interfaces — Consumes:** Task 1. **Produces:**
- `createPkce(random?: (n: number) => Buffer): { verifier: string; challenge: string; state: string }` (verifier 43–128 chars base64url; challenge = base64url(SHA-256(verifier))).
- `startLoopback({ state, timeoutMs = 300_000 }): Promise<{ redirectUri: string; code: Promise<string>; close(): void }>` — escucha en `127.0.0.1:0`; acepta solo `GET /callback`; `state` distinto → 400 y sigue esperando; `?error=access_denied` → rechaza con `denied`; al recibir el código responde un HTML mínimo y se cierra; a los 5 min rechaza con `timeout`.
- `GmailAuthError` con `code: 'cancelled' | 'timeout' | 'denied' | 'network' | 'invalid-response'`.
- `createGmailAuth({ fetch, openExternal, oauthBase, clientId, clientSecret })` → `{ signIn(): Promise<{ refreshToken: string; accessToken: string; expiresAt: number }>; cancel(): void; refresh(refreshToken: string): Promise<{ accessToken: string; expiresAt: number }>; revoke(token: string): Promise<void> }`. URL de autorización con `client_id`, `redirect_uri`, `response_type=code`, `scope` de Global Constraints, `code_challenge`, `code_challenge_method=S256`, `state`, `access_type=offline`, `prompt=consent`. Un `signIn` en curso se cancela si empieza otro.

- [ ] Tests: challenge del vector del RFC 7636 (apéndice B); loopback con peticiones reales a `127.0.0.1` (state malo → 400 y sigue; `POST` → 405; otra ruta → 404; código bueno → resuelve y cierra; `error` → `denied`; timeout con temporizadores falsos); `signIn` abre una URL con todos los parámetros y cambia el código (fetch falso) por tokens con `code_verifier`; segundo `signIn` → el primero rechaza `cancelled`; `cancel` cierra el servidor; `refresh` y `revoke` envían los campos correctos; respuesta de token inválida → `invalid-response`.
- [ ] RED → GREEN.
